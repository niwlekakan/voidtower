sqlx 0.9.1 was required: sqlx 0.8.x pins libsqlite3-sys <0.31, so the only path
to a patched libsqlite3-sys is the sqlx major bump. The 0.9 API change is
mechanical and was applied as follows:

- Every dynamic SQL string passed to a query function is wrapped in
  sqlx::AssertSqlSafe(...). All wrapped strings are built from compile-time
  constants (SELECT_* / TERMINAL_JOB_STATES constants), from quoted_identifier()
  for PRAGMA identifiers, or from a fixed test-local table array. No user input
  is interpolated; user values are bound with .bind() as before.
- QueryBuilder lifetime parameter removed (timeline.rs).
- Cargo feature names changed: runtime-tokio-rustls -> runtime-tokio plus
  tls-rustls-ring (same TLS backend as before, rustls ring provider).

Ignore list: backend/deny.toml now lists RUSTSEC-2023-0071 (unchanged) and
RUSTSEC-2026-0543 (new, unmaintained warning, not a vulnerability). Both are
reached only through the git-pinned openidconnect 4.1.0 (commit e20ddbb0).
Tracking: this file; re-check after any openidconnect pin change.
CI: .github/workflows/ci.yml cargo audit now passes both --ignore flags, matching deny.toml.

## Pre-existing test failures (not caused by M1)

All 21 failing tests are environmental or pre-existing, and were verified to
fail identically on the untouched base commit d925769:

- 20 x agent::state / agent::supervision / agent::tests permission checks:
  "agent state parent chain contains an unsafe writable directory". The
  sandbox home /home/elwla/.hermes/profiles is group-writable, which the
  state code rejects by design. Base commit fails 16 of these in the
  agent::state filter alone.
- 1 x operations::registry::tests::shared_jobs_and_approvals_surfaces_are_source_enforced:
  "missing shared operation route path=\"jobs\"" (a frontend source assertion).

These need an environment with a non-group-writable parent chain, and a
separate fix for the frontend route assertion. They are NOT part of M1 and were
not hidden or ignored. Blocked on: a clean test host, or a separate milestone.
