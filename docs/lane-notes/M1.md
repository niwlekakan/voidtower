## Implemented

- `backend/Cargo.toml` moves sqlx 0.8.6 to 0.9.1. The 0.8 line constrains
  `libsqlite3-sys` below the patched release. Feature names now use
  `runtime-tokio` plus `tls-rustls-ring`, retaining the rustls ring backend.
- `backend/Cargo.lock` contains the dependency upgrades listed above and their
  transitive resolution changes.
- The sqlx 0.9 API migration wraps dynamic SQL in `sqlx::AssertSqlSafe` and
  removes the obsolete `QueryBuilder` lifetime. Dynamic strings are built only
  from compile-time constants, fixed test table names, or `quoted_identifier`;
  user values remain bound with `.bind()` as before.
- `.github/workflows/ci.yml` and `backend/deny.toml` use the same two narrow
  advisory exceptions documented below. No other advisories are ignored.
- `backend/src/operations/registry.rs` corrects a stale test-only source lookup:
  the route table is in `frontend/src/AppRoutes.tsx`, not `App.tsx`. No frontend
  or backend production source is changed by this correction.
- Two accidentally committed `.voidtower-supervision-collector-*.sh` test
  artifacts were removed; they are generated by an agent supervision test and
  are not product source.
- No HTTP route or handler registration was edited. A direct comparison of
  `backend/src/api/mod.rs` against `main` found the file byte-identical, with
  330 route registrations in each revision and zero additions or removals.

## Residual advisory exceptions and tracking

### RUSTSEC-2023-0071 (rsa 0.9.10)

RustSec lists rsa 0.10.0 as patched. The latest upstream `openidconnect` 4.1.0
release (`e20ddbb01ca68356f2979bc125f5613ab45b4e7e`) still declares rsa 0.9.2,
which resolves to 0.9.10, so there is no fixed compatible upstream release to
select. The open crypto-upgrade PR also currently selects the release candidate
`0.10.0-rc.20`, not the patched stable 0.10.0 release. Vendoring and modifying
that third-party crypto migration is not a dependency-only remediation.

Tracking: <https://github.com/ramosbugs/openidconnect-rs/pull/244>.
Recheck on every OpenID Connect update; select a release that uses rsa >=0.10.0
and remove this exception. This exception predates M1; its reason and tracking
were corrected rather than extending it to another advisory.

### RUSTSEC-2026-0543 (chrono 0.4.45)

This is an informational unmaintained warning, not a vulnerability. RustSec
lists no patched chrono versions, and 0.4.45 is already the latest release.
Both `openidconnect` and its `oauth2` dependency still require chrono.

Tracking: <https://github.com/ramosbugs/openidconnect-rs/issues/256> and
<https://github.com/ramosbugs/oauth2-rs/issues/351>. Recheck after those
migrations and remove this exception when chrono leaves the dependency graph.

The successful test invocation was `cargo test` with `TMPDIR` set to
`/home/elwla/.hermes/profiles/kestvik/cache/scratch/m1-test-tmp` and `umask 077`.
The agent-state tests intentionally fail closed if a temp-directory ancestor is
group-writable. For this run only, the existing 0775 profile and cache ancestors
were changed to 0755 and restored immediately afterward; the temp directory was
0700. This avoids host-permission false failures without changing or ignoring
any test. On a normal CI host with a safe temp-directory chain, plain
`cargo test` needs no such adjustment.
